# Пример: реестр точек ввода данных

> Учебный пример на **вымышленном** проекте «Электронная библиотека» (Vue + Laravel).
> Как проверяли: клиент — атрибуты формы и код компонента; сервер — `$request->validate(...)` в контроллере или класс FormRequest.

| № | Точка ввода | Поля | Проверка на клиенте | Проверка на сервере | Риск |
|---|---|---|---|---|---|
| 1 | Форма регистрации → `POST /api/register` | name, email, password | да: `required`, `type="email"`, `minlength="8"` | да: `validate()` в `AuthController@register:24` | низкий |
| 2 | Форма входа → `POST /api/login` | email, password | да: `required` | да: `validate()` | перебор паролей — нет ограничения числа попыток |
| 3 | Поиск по каталогу → `GET /api/books?q=` | q | нет | **нет**: `q` подставляется в `whereRaw("title LIKE '%$q%'")`, `BookController@index:18` | **высокий**: SQL-инъекция |
| 4 | Отзыв о книге → `POST /api/books/{id}/reviews` | text, rating | да: `maxlength="1000"` | частично: `rating` проверяется, `text` — нет | **высокий**: XSS — текст выводится через `v-html` в `BookCard.vue:56` |
| 5 | Оформление выдачи → `POST /api/loans` | user_id, copy_id | да: выпадающие списки | да: `exists:users,id`, `exists:copies,id` | средний: роль «библиотекарь» проверяется только на клиенте (кнопка скрыта), на сервере нет |
| 6 | Загрузка обложки → `POST /api/books/{id}/cover` | file | да: `accept="image/*"` | **нет**: тип и размер файла не проверяются | **высокий**: загрузка произвольного файла |
| 7 | Параметр страницы → `GET /api/books?page=` | page | нет | да: Laravel приводит к числу | низкий |

Итого точек: 7, без серверной проверки (полностью или частично): 4 — № 3, 4, 5, 6.

Самые рискованные — № 3 (SQL-инъекция) и № 6 (загрузка файлов): данные из запроса попадают в SQL и файловую систему без проверки.
