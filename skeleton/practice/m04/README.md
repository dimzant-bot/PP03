## 2. Линтер

Линтер: PHP_CodeSniffer version 4.0.4 (название, версия). Команда проверки: php phpcs.phar --report=summary и php phpcs.phar --report=source

Отключённые правила и почему:
- Generic.Files.LineLength — в шаблонах смешиваются HTML и PHP, допустимы длинные строки.
- PSR1.Files.SideEffects — в шаблонах допустимы побочные эффекты.
- PSR1.Classes.ClassDeclaration.MissingNamespace — проект не использует пространства имён и автозагрузку.
- Squiz.ControlStructures.ControlSignature — используется альтернативный синтаксис PHP.
- Squiz.WhiteSpace.ScopeClosingBrace — используется альтернативный синтаксис PHP.
- PSR12.Files.FileHeader — для шаблонов не требуется стандартная проверка заголовков файлов

Какие правила нарушались чаще всего:
- Generic.WhiteSpace.DisallowTabIndent.TabsUsed — 78 нарушений.
- PSR2.Files.EndFileNewline.NoneFound — 8 нарушений.
- Generic.ControlStructures.InlineControlStructure.NotAllowed — 3 нарушения.
- PSR12.Files.FileHeader.SpacingAfterTagBlock — 3 нарушения.

## 5. Сравнение способов передачи настроек

| Способ | Что передаёт | Плюсы | Минусы | Когда использовать |
|---|---|---|---|---|
| Файлы в репозитории (`.editorconfig`, `.vscode/`, `phpcs.xml`) | Настройки форматирования, линтера и IDE | Доступны всем участникам проекта | Нужно поддерживать файлы в актуальном состоянии | Для командной разработки |
| Экспорт профиля / настроек IDE в файл | Персональные настройки редактора | Можно перенести настройки на другой компьютер | Не всегда переносится всё окружение | При смене компьютера |
| Синхронизация через аккаунт (Settings Sync) | Настройки IDE через аккаунт | Автоматическая синхронизация | Требуется аккаунт и подключение | Для личной работы на нескольких устройствах |

Вывод: Для командной разработки наиболее подходящим способом является хранение общих настроек непосредственно в Git-репозитории. Это позволяет всем участникам проекта использовать одинаковые правила форматирования, настройки линтера и рекомендации по расширениям.
В ходе работы я настроил .gitattributes, .editorconfig, phpcs.xml и файлы .vscode/, благодаря чему основные параметры разработки стали доступны вместе с исходным кодом проекта.
Экспорт профиля VS Code и настроек NetBeans полезен для переноса индивидуальной конфигурации на другой компьютер, но не заменяет общие настройки проекта.
При проверке PHP_CodeSniffer было обнаружено 96 нарушений в 13 файлах. После автоматического исправления осталось одно нарушение в одном файле, что показало необходимость дополнительного контроля качества кода.
Также выяснилось, что Apache NetBeans в проведённом эксперименте не соблюдал настройки .editorconfig, поэтому для него пришлось отдельно настроить форматирование проекта.
Самостоятельная проверка в чистом окружении показала, что после форматирования 3–5 файлов команда git diff не выявила изменений. Это подтверждает согласованность настроек форматирования в проверенном окружении.
Полученные знания пригодятся в следующих модулях при совместной разработке, работе с Git, настройке IDE, автоматической проверке качества кода и подготовке проекта для новых участников команды.
