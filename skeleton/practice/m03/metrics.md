## 2. Где меняется каждая характеристика

Проверьте в обеих средах. Если среда чего-то не умеет — так и напишите: это тоже результат.

| Характеристика | VS Code | Apache NetBeans вторая IDE |
|---|---|---|
| Кодировка файла | В строке состояния - UTF-8 | свойства проекта → Sources → Encoding (для всего проекта) |
| Окончания строк (LF / CRLF) | В строке состояния → LF / CRLF | Зависит от настроек проекта и редактора; проверить фактические окончания строк файла |
| Табуляция → пробелы | строка состояния → Tab Size → Convert Indentation to Spaces | Tools → Options → Editor → Formatting → Expand Tabs to Spaces, затем форматирование |
| Форматирование файла | Shift + Alt + F | Alt + Shift + F |
| Переименование переменной / метода | F2 | Ctrl + R |
| Выделение метода (Extract Method) | Code Actions / Refactor, зависит от языка и расширений | Refactor → Extract Method, если поддерживается для выбранного языка |
| Инспекция кода (поиск проблем) | Вкладка Problems | Окна Navigator, Output и подсветка ошибок редактора; дополнительные проверки зависят от языка и плагинов |
| Где хранятся настройки (файл / папка) | settings.json пользователя или .vscode/ проекта | Tools → Options; проект — nbproject/ |

## 4. Конфликт форматирования

Файл: Auth.php. `git diff --stat` после форматирования во второй IDE: 56 строк изменено.

Чем отличаются форматтеры (отступы, переносы, пробелы, скобки): изменилось положение фигурных скобок (в одной версии на новой строке, в другой — на той же строке), переносы строк в объявлениях методов, количество пустых строк и расположение блоков кода. Также различаются окончания строк LF и CRLF.

Чем это плохо для команды: появляются лишние изменения в Git, усложняется просмотр git diff, труднее находить реальные изменения логики программы. Разработчикам приходится тратить время на исправление форматирования вместо работы над функциональностью.
