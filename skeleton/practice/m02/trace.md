# Трассировка сценариев

Картинка DFD: `dfd.drawio` + `dfd-0.png` (контекстная) + `dfd-1.png` (уровень 1).

## Элементы DFD

| Тип | Название | Описание |
|---|---|---|
| Внешняя сущность | Читатель | Посетитель/зарегистрированный пользователь. Просматривает каталог и карточки книг, регистрируется, входит в систему, бронирует книги, оставляет отзывы. |
| Внешняя сущность | Библиотекарь |	Пользователь с ролью librarian. Выдаёт и принимает книги, просматривает бронирования и должников, добавляет книги и обложки. |
| Внешняя сущность | Администратор | Пользователь с ролью admin. Управляет пользователями, ролями и блокировками; имеет доступ к административным функциям. |
| Внешняя сущность | Браузер пользователя | Отображает HTML-интерфейс и отправляет формы/HTTP-запросы к PHP-приложению. |
| Процесс | Регистрация и авторизация | Принимает данные регистрации и входа, проверяет их, создаёт пользователя и поддерживает авторизованную сессию. public/index.php, src/Auth.php. |
| Процесс | Поиск и просмотр каталога | Ищет книги по названию/автору, фильтрует по жанру, сортирует и показывает карточку книги. public/api.php, src/BookRepository.php. |
| Процесс | Бронирование и отмена бронирования | Создаёт активное бронирование книги и позволяет отменить его. public/api.php, src/LoanService.php, src/ReservationRepository.php. |
| Процесс | Учет выдачи и возврата | Выдаёт экземпляр читателю, принимает возврат, рассчитывает штраф и меняет статус экземпляра. src/LoanService.php. |
| Процесс | Работа с отзывами | Получает список отзывов и сохраняет отзыв с оценкой. public/api.php, src/ReviewRepository.php. |
| Процесс | Администрирование библиотеки | Управляет книгами, экземплярами, пользователями, ролями, блокировками и обложками. public/index.php, public/api.php, репозитории. |
| Процесс | Формирование отчетов | Показывает должников, статистику и популярные книги; формирует CSV-выгрузку должников. src/ReportService.php. |
| Хранилище | users | 	Таблица пользователей: ФИО, email, хеш пароля, роль, категория, группа, телефон, блокировка, дата создания. |
| Хранилище | books | Таблица библиографических записей книг и имени файла обложки. |
| Хранилище | genres | Справочник жанров. |
| Хранилище | copies | Физические экземпляры книг, инвентарные номера и статусы доступности. |
| Хранилище | loans | История выдачи/возврата, даты, читатель, библиотекарь и штраф. |
| Хранилище | reservations | Бронирования книг, пользователь, дата создания и статус. |
| Хранилище | reviews | Отзывы читателей, оценка, текст и дата создания. |
| Хранилище | public/uploads/ | Файлы обложек книг. |
| Хранилище | PHP-сессия | Идентификатор авторизованного пользователя ($_SESSION['user_id']) и flash-сообщение. Физический способ хранения определяется настройками PHP. |

## Сценарий 1: «Регистрация пользователя»

| Шаг | Где (файл:строка) | Функция / endpoint | Какие данные передаются |
|---|---|---|---|
| 1. Пользователь заполняет форму | templates/register.php:3-28 | register-form, method="post", action="index.php?page=register" | full_name, email, password, category, group_name, phone. |
| 2. Клиент отправляет запрос | templates/register.php:3; обработчик — public/index.php:38-42 | POST index.php?page=register | Данные формы передаются как обычные поля HTML-формы (application/x-www-form-urlencoded при стандартной отправке браузером). |
| 3. Сервер обрабатывает | public/index.php:40-45; src/Validator.php:12-23,33-38,57-64 | new Validator($_POST), required(), minLength() | Проверяются наличие full_name, email, password и минимальная длина пароля 6 символов. |
| 4. Запись в БД | public/index.php:46; src/Auth.php:47-63; src/Database.php:45-50 | Auth::register($_POST) → Database::insert() | В users записываются ФИО, email, MD5 от пароля, роль reader, категория, группа, телефон и дата создания. |
| 5. Ответ клиенту | public/index.php:47-50; src/helpers.php:8-12 | $_SESSION['user_id'] = $id, flash(), redirect('catalog') | В сессии сохраняется ID нового пользователя; браузеру отправляется HTTP-редирект на index.php?page=catalog (обычно статус 302). |

Запрос из DevTools (HAR сохранён как `scenario1.har`): метод, URL, код ответа, тело — POST, inder.php?page=register, тело: поля full_name, email, password, category, group_name, phone, успешный ответ: редикерт на index.php?page=catalog; функция redirect() задает заголовок Location, но фактический статус и обмен нужно подтвердить HAR.

## Сценарий 2: «Бронирование книги читателем»

| Шаг | Где (файл:строка) | Функция / endpoint | Какие данные передаются |
|---|---|---|---|
| 1. Читатель открывает карточку книги и нажимает «Забронировать» | templates/book.php:2,22-27 | Кнопка #reserve-btn; ID книги находится в data-book-id | book_id берётся из ID отображаемой книги. Кнопка показывается авторизованному пользователю. |
| 2. JavaScript отправляет запрос | public/assets/js/book.js:58-65; public/assets/js/api.js:4-21 | api('reserve', { method: 'POST', body: { book_id: bookId } }) | POST api.php?action=reserve, JSON-тело {"book_id": <ID книги>}; заголовок Content-Type: application/json. |
| 3. API проверяет авторизацию и читает JSON | public/api.php:56-61; src/helpers.php:78-83 | Ветка case 'reserve', Auth::check(), request_json() | Из тела запроса извлекается book_id; ID текущего читателя берётся из Auth::user()['id']. Если пользователь не вошёл, API возвращает ошибку 401. |
| 4. Сервис проверяет повторное активное бронирование и записывает новое | src/LoanService.php:159-173; src/Database.php:23-27,45-50 | LoanService::reserve($bookId, $userId) | Проверяется наличие активной записи с такими book_id и user_id; при отсутствии добавляется строка в reservations с created_at и статусом active. |
| 5. API возвращает результат, JavaScript показывает сообщение | public/api.php:60-61; src/helpers.php:15-21; public/assets/js/book.js:61-64 | json_response(...); обработчик результата api() | JSON с ok и message: при успехе сообщение «Книга забронирована», при повторном бронировании — «Вы уже забронировали эту книгу». При успехе кнопка блокируется. |

## Расхождения

Что в коде не совпало с тем, что вы ожидали по интерфейсу:
1. В регистрации сервер не проверяет формат email — `public/index.php`.
2. Пароль хранится через MD5 вместо безопасного хеширования — `src/Auth.php`.
3. При бронировании не проверяется наличие свободных экземпляров — `src/LoanService.php`.
