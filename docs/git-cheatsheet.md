# Шпаргалка по Git для практики

## Каждый день

```
git status                         # что изменено
git add файл                       # подготовить файл к коммиту (git add . — всё)
git commit -m "fix: описание"      # коммит
git push                           # отправить на сервер
git pull                           # забрать изменения
```

## Ветки

```
git switch main                   # перейти на основную ветку
git pull                          # и обновить её
git switch -c practice/m05         # создать ветку модуля и перейти в неё
git branch -a                      # все ветки
git push -u origin practice/m05    # первая отправка новой ветки
```

## Сообщения коммитов (Conventional Commits)

| Тип | Когда | Пример |
|---|---|---|
| `feat:` | новая возможность | `feat: проверка email на клиенте` |
| `fix:` | исправление ошибки | `fix #12: параметризован запрос поиска` |
| `docs:` | документация, отчёты | `docs: паспорт проекта` |
| `refactor:` | переделка без изменения поведения | `refactor: выделен метод calcTotal` |
| `test:` | тесты | `test: характеризационные тесты calcPrice` |
| `style:` | форматирование | `style: автоформатирование по .editorconfig` |
| `chore:` | служебное | `chore: add practice skeleton` |
| `ci:` | CI | `ci: линтер и тесты в GitHub Actions` |

## Исследование истории

```
git log --oneline --graph --all --decorate -n 40
git log --follow --oneline -- путь/к/файлу      # история одного файла
git blame путь/к/файлу                          # кто написал каждую строку
git show <хеш>                                  # что изменилось в коммите
git diff                                        # несохранённые изменения
git diff --stat main..practice/m03              # отличия ветки от main
```

## Если что-то пошло не так

| Ситуация | Команда |
|---|---|
| Исправить сообщение последнего коммита (ещё не отправлен) | `git commit --amend -m "новое сообщение"` |
| Убрать файл из подготовленных к коммиту | `git restore --staged файл` |
| Отменить изменения в файле | `git restore файл` |
| Случайно закоммитил `.env` (ещё не отправлен) | `git rm --cached .env`, добавить `.env` в `.gitignore`, `git commit --amend` |
| Закоммитил и **отправил** пароль | сменить пароль/ключ немедленно — из истории его уже скачали; сообщить руководителю |
| `push` отклонён: `rejected … fetch first` | `git pull --rebase`, затем `git push` |
| Конфликт при слиянии | открыть файл, найти `<<<<<<<`, оставить нужное, `git add`, `git commit` |

## Pull Request

1. Отправьте ветку: `git push -u origin practice/m05`.
2. На сайте: Compare & pull request (GitHub) / Создать запрос на слияние (GitFlic).
3. Заполните шаблон описания и влейте PR (позже в практике появятся ревью и автоматические проверки).
4. Merge → удалить ветку → локально `git switch main`, затем `git pull`.
