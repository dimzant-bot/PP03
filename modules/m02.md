## Шаг 1. Элементы DFD

DFD (диаграмма потоков данных) состоит из четырёх элементов:

| Элемент | Обозначение | Что это в вашем проекте |
|---|---|---|
| Внешняя сущность | прямоугольник | пользователь, администратор, внешний API, почтовый сервис |
| Процесс | круг / скруглённый прямоугольник | «Регистрация», «Оформление заказа» — то, что преобразует данные |
| Хранилище | две параллельные линии | таблица БД, файл, кэш, localStorage |
| Поток | стрелка с подписью | «логин, пароль», «список товаров» |

Выпишите их в таблицу «Элементы DFD» в `practice/m02/trace.md`. Источники: маршруты (`routes/`, `urls.py`, контроллеры), модели/миграции, формы на клиенте.

## Шаг 2. Диаграммы в draw.io

1. Установите draw.io (desktop) или расширение Draw.io Integration в VS Code.
2. Создайте `practice/m02/dfd.drawio`. Лист 1 — **контекстная диаграмма**: вся система одним процессом + внешние сущности.
   Лист 2 — **уровень 1**: 4–8 основных процессов, хранилища, потоки.
3. Экспорт: File → Export as → PNG → `dfd-0.png`, `dfd-1.png`.

Правила: у каждой стрелки есть подпись; данные не идут напрямую из хранилища в сущность — только через процесс.

## Шаг 3. Трассировка двух сценариев

Выберите два сценария, где пользователь **вводит** данные (регистрация, создание записи, поиск).
Пройдите по коду от кнопки до БД и обратно:

1. Найдите форму на клиенте (поиск по тексту кнопки: Ctrl+Shift+F в VS Code).
2. Найдите, куда уходит запрос (`fetch`, `axios`, `action="..."`, Retrofit-интерфейс).
3. Найдите обработчик маршрута на сервере.
4. Найдите запрос к БД (ORM-метод или SQL).
5. Найдите, что возвращается клиенту.

Заполните таблицы в `trace.md`, указывая `файл:строка`.

## Шаг 4. Перехват запросов

1. Откройте клиент в браузере → F12 → вкладка **Network** → включите *Preserve log*.
2. Выполните сценарий. Найдите запрос, посмотрите Headers, Payload, Response.
3. Сохраните: правый клик → *Save all as HAR* → `practice/m02/scenario1.har`.
4. **Важно:** HAR содержит cookies и токены. Делайте это под тестовым пользователем, а перед коммитом
   найдите в файле `password`, `token`, `Authorization` и замените значения на `***`.

Мобильный проект: используйте Network Inspector в Android Studio или логирование запросов на сервере.

## Шаг 5. Реестр точек ввода

В `input-points.md` перечислите **все** места, где в систему попадают данные извне: формы, параметры URL,
тела API-запросов, загрузка файлов, заголовки. Для каждой отметьте, проверяется ли ввод на клиенте и на сервере.
Как проверить серверную проверку: отправьте пустое/неверное значение в обход формы (подробно — в М13), или найдите в коде валидатор.
