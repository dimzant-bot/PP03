**Цель:** измерить характеристики кода, изменить их средствами двух сред разработки и сравнить среды.
**Берём из М01:** горячие точки. **Передаём:** замер «до» → М10 и М13; проблема «каждая среда форматирует по-своему» → М04.

## Шаг 1. Две среды (1 ч)
VS Code (+ расширения PHP Intelephense, EditorConfig) и вторая среда: Apache NetBeans или PhpStorm.
`nbproject/` и `.idea/` пока не коммитить.

## Шаг 2. Замер «до» (2 ч)
```
python ПУТЬ\pp03-ispo332\tools\metrics.py . --label "М03 до" --out practice\m03\metrics-raw.md
git ls-files --eol
git grep -l -P "^\t" -- "*.php"
```
Инспекции: VS Code — Problems (Ctrl+Shift+M); NetBeans — Window → Action Items (Ctrl+6); PhpStorm — Code → Inspect Code.
Скриншоты, столбец «до» в `metrics.md`.

## Шаг 3. Где что меняется (3 ч)
Таблица в `metrics.md`: кодировка, LF/CRLF, табы → пробелы, форматирование, переименование, выделение метода,
инспекция, где хранятся настройки — для VS Code и второй среды. Не умеет — так и писать.

| | VS Code | NetBeans | PhpStorm |
|---|---|---|---|
| Форматирование | Shift+Alt+F | Alt+Shift+F | Ctrl+Alt+L |
| Переименование | F2 | Ctrl+R | Shift+F6 |
| Выделение метода | ? | ? | Ctrl+Alt+M |

## Шаг 4. Изменения (4 ч) — каждое отдельным коммитом
1. Файл с табуляцией → пробелы: `style: ... — отступы пробелами`
2. Файл с `i/crlf` → LF: `style: окончания строк LF`
3. 2–3 переменные из одной буквы → понятные имена (через IDE): `refactor: ...`
4. Самую сложную функцию разбить на методы до сложности ≤ 10 и длины ≤ 50 строк: `refactor: выделен метод ...`

Хотя бы одно изменение — во второй среде.
**До и после** — контрольный прогон 3–4 сценариев в приложении, ответы должны совпасть.
**Ошибки логики не исправлять** — записать в «Находки».

## Шаг 5. Конфликт форматирования (2 ч)
Файл из `src/`: форматировать в VS Code → коммит → форматировать во второй среде → `git diff --stat`, `git diff` → скриншот →
`git restore файл`. Пустой diff — повторить на файле из `templates/`.
